# Mobile Performance Audit - David Test Scenes

Date: 2026-06-05

Scope:

- `Assets/Scenes/David_Test.unity`
- `Assets/Scenes/IntroPetSelection.unity`
- `Assets/Scenes/Walking.unity`

These are the three enabled scenes in `ProjectSettings/EditorBuildSettings.asset`. I treated "Pet Selector and Walking" as the named parts of this build path, with `David_Test` as the third David test scene because it is first in the enabled build scene list.

## Executive Summary

The biggest mobile performance opportunities are in this order:

1. Bake or strip Walking's SplineMesh authoring/runtime stack from the mobile runtime scene.
2. Replace Walking's heavy mesh-collider road setup with simple authored route and collision proxies.
3. Tighten mobile URP renderer settings: remove decals unless required, prefer forward rendering, turn off soft shadows for Balanced, and consider defaulting mobile tests to Battery on weaker devices.
4. Change Pet Selector startup from "load all definitions and spawn the full test roster immediately" to lazy or pooled pet previews.
5. Extend mobile texture import optimization beyond UI/window backdrops to pets, city props, terrain, and large third-party textures.
6. Reduce runtime scene-wide discovery in hot paths and startup code, especially `FindObjectsByType` loops in Walking and living room graphics setup.

## High Priority Findings

### 1. Walking carries runtime SplineMesh authoring components

Evidence:

- `Walking.unity` has 77 `SplineMeshTiling`, 77 `Spline`, 77 `MeshBender`, and 62 `SplineSmoother` components.
- It also has 77 objects named `generated by SplineMeshTiling` and 77 `segment 1 mesh` objects.
- `SplineMeshTiling.Update()` runs every frame on each component, even though it returns early when `updateInPlayMode` is false.
- `MeshBender.LateUpdate()` calls `ComputeIfNeeded()` every frame on each `MeshBender`.

Why it matters:

Even if most generated meshes are static, hundreds of MonoBehaviour callbacks and event subscriptions are unnecessary in a mobile walking scene. If any spline marks itself dirty, `MeshBender` performs mesh rebuild work and updates mesh collider data.

Recommended fix:

- Create a baked mobile walking scene variant or editor bake step:
  - Bake spline-generated meshes into static mesh assets or saved child meshes.
  - Remove/disable `SplineMeshTiling`, `Spline`, `MeshBender`, and `SplineSmoother` from runtime builds.
  - Keep only MeshRenderer/MeshFilter and deliberately chosen colliders.
- Short-term mitigation: disable these components on mobile after scene load once generated meshes exist, but prefer asset baking to avoid startup callback churn.

Relevant code:

- `Assets/SplineMesh/Scripts/MeshProcessing/SplineMeshTiling.cs`
- `Assets/SplineMesh/Scripts/MeshProcessing/MeshBender.cs`
- `Assets/Scenes/Walking.unity`

### 2. Walking uses 89 mesh colliders and no simple collider proxies

Evidence:

- `Walking.unity` has 89 `MeshCollider` components, 0 `BoxCollider`, 0 `SphereCollider`, and 0 `CapsuleCollider`.
- `PawPalWalkingSceneBindings.AutoAssignAllowedRoadsFromScene()` scans scene colliders for each default road name.
- `PawPalWalkSceneController.ProjectToAllowedRoad()` checks raycast hits against `allowedRoads.Contains(...)` during walker projection.

Why it matters:

Mesh colliders are expensive for physics broadphase/narrowphase and memory. For a guided walk, the dog only needs a simple path, ground height, and leash interaction zones.

Recommended fix:

- Author a lightweight route graph and route-height samples in `PawPalWalkingSceneBindings` so startup does not need collider discovery.
- Replace road mesh colliders with:
  - a few flat box colliders for road surface projection, or
  - a baked route path with sampled height values and no road collision dependency for normal walking.
- Keep detailed mesh colliders only where player interaction genuinely needs them.
- Cache `allowedRoads` as a `HashSet<Collider>` if per-frame projection remains.

Relevant code:

- `Assets/Scripts/Walk/PawPalWalkingSceneBindings.cs`
- `Assets/Scripts/Walk/PawPalWalkSceneController.cs`
- `Assets/Scenes/Walking.unity`

### 3. Mobile renderer still enables costly generic features

Evidence:

- `Assets/Settings/Mobile_Renderer.asset` includes an active `DecalRendererFeature`.
- The same renderer is shared by Battery, Balanced, and Quality mobile RP assets.
- `Mobile_Renderer.asset` has `m_RenderingMode: 2`, which should be verified in Unity; if this is Deferred, it is a poor default for mobile.
- `Mobile_RPAsset.asset` has soft shadows enabled and `m_AdditionalLightsPerObjectLimit: 1`.
- `PawPalGraphicsSettings` defaults mobile to Balanced and targets 60 FPS for Balanced/Quality.

Why it matters:

The mobile renderer should be aggressively feature-specific. Decals, soft shadows, unnecessary additional lights, and deferred paths are common GPU/bandwidth costs on phones.

Recommended fix:

- Split mobile renderer data into at least:
  - `MobileBattery_Renderer`: forward, no decals, no global volume feature if unused, no soft shadows.
  - `MobileBalanced_Renderer`: forward, decals only if Walking asphalt decals are visually required.
  - `MobileQuality_Renderer`: optional decals/soft shadows.
- Set Balanced soft shadows off unless device profiling proves budget.
- Verify `m_RenderingMode` in Unity and use Forward/Forward+ only when it clearly wins on target devices.
- Consider starting David mobile test builds in Battery preset by default, then allowing upgrade to Balanced.

Relevant assets/code:

- `Assets/Settings/Mobile_Renderer.asset`
- `Assets/Settings/Mobile_RPAsset.asset`
- `Assets/Settings/MobileBattery_RPAsset.asset`
- `Assets/Scripts/Environment/PawPalGraphicsSettings.cs`

### 4. Pet Selector spawns the full test roster on startup

Evidence:

- `IntroPetSelectionController.Initialize()` calls `spawner.LoadDefinitions()`, builds a roster, then immediately calls `spawner.Spawn(selections)`.
- `IntroPetSpawner.LoadDefinitions()` uses `Resources.LoadAll<IntroPetDefinition>("PawPal/IntroPets/Definitions")`.
- `IntroPetSpawner.Spawn()` loops through every selected pet and instantiates each one.
- `IntroPetSpawner.CreateAgent()` adds runtime NavMeshAgent/dog/cat components and configures LOD groups after instantiation.

Why it matters:

Pet Selector startup cost scales with roster size and prefab weight. Even if the selector scene file is small, loading definitions and instantiating several animated pet prefabs can spike CPU, memory, shader warmup, and texture upload on mobile.

Recommended fix:

- Load definition metadata first, but instantiate only the selected/current pet plus one neighbor on either side.
- Pool pet preview instances instead of destroying/instantiating on breed/fur changes.
- Preload or async load pet prefabs one at a time with a transition overlay.
- Store a mobile-specific selector roster that avoids loading all definition assets through `Resources.LoadAll`.
- For fur changes, prefer material swaps over variant prefab respawn; the current path already supports in-place material swaps when `ReplacementMaterial` exists.

Relevant code:

- `Assets/Scripts/Intro/IntroPetSelectionController.cs`
- `Assets/Scripts/Intro/IntroPetSpawner.cs`
- `Assets/Resources/PawPal/IntroPets/Definitions/`

## Medium Priority Findings

### 5. Texture import optimization is too narrow

Evidence:

- `PawPalMobileTextureImportPostprocessor` only targets `Assets/Resources/UI` and `Assets/Resources/WindowBackdrops`.
- Pet, city, terrain, apartment, and other third-party art textures are outside that postprocessor.
- Walking relies heavily on Japanese City Megapack prefabs.
- Intro Pet Selection uses third-party trees, fences, lamp posts, and pet/toy props.

Recommended fix:

- Extend mobile texture platform settings to:
  - `Assets/3rd Party Packs/Japanese City Megapack`
  - `Assets/3rd Party Packs/Dogs (Red Deer)`
  - `Assets/3rd Party Packs/Realistic Tree`
  - `Assets/3rd Party Packs/Brick Project Studio`
  - `Assets/Terrains`
- Use ASTC for Android/iOS where available, with fallback strategy if older Android devices are required.
- Cap most environment textures at 1024 or 512 on mobile; reserve 2048 only for first-person/close inspection assets.
- Enable mipmaps and streaming mipmaps for 3D world textures. The current UI postprocessor correctly disables mipmaps for sprites, but world textures need them.

Relevant code:

- `Assets/Editor/PawPalMobileTextureImportPostprocessor.cs`
- `ProjectSettings/QualitySettings.asset`

### 6. Runtime scene-wide discovery should be reduced

Evidence:

- `LivingRoomGraphicsEnhancer` applies graphics on `OnEnable`, again in `Start`, and then checks every `Update` for time-of-day changes.
- Its apply path repeatedly calls `FindObjectsByType` for lights, cameras, renderers, terrain, dog agents, and backdrop controllers.
- `PawPalWalkSceneController.Start()` calls `FindInSceneOrCreateRuntimeFallback()` and then `AutoAssignAllowedRoadsFromScene()` again.
- `PawPalWalkingSceneBindings.AutoAssignAllowedRoadsFromScene()` scans all colliders inside a loop over default road names.

Recommended fix:

- Apply `LivingRoomGraphicsEnhancer` once at scene load and then on explicit minute/hour transitions, not both `OnEnable` and `Start`.
- Cache scene renderer/light/camera lists after scene load unless objects are expected to be added.
- In Walking, serialize the allowed road colliders or route graph and skip auto-discovery in player builds.
- Replace repeated collider scans with one scan into a dictionary by object name, or remove the scan entirely for authored scenes.

Relevant code:

- `Assets/Scripts/Environment/LivingRoomGraphicsEnhancer.cs`
- `Assets/Scripts/Walk/PawPalWalkingSceneBindings.cs`
- `Assets/Scripts/Walk/PawPalWalkSceneController.cs`

### 7. Walking route progress writes every frame

Evidence:

- `PawPalWalkSceneController.Update()` calls `PushProgressToRuntime()` every frame while running.
- Progress is also pushed on pause and completion paths.

Recommended fix:

- Throttle runtime progress writes to every 0.25-0.5 seconds, on significant percentage deltas, and on pause/complete.
- Keep visual walking smooth locally; only reduce persistence/runtime-state updates.

Relevant code:

- `Assets/Scripts/Walk/PawPalWalkSceneController.cs`

## Scene-Specific Recommendations

### David_Test

- Profile instantiated object counts, not just scene YAML counts; the scene is prefab-driven.
- Reduce or bake fill lights where possible. The scene contains 4 lights, including fill lights and a reflection probe.
- Consider disabling post-processing in default mobile Balanced for David tests. `PawPalGraphicsSettings.EnablePostProcessing` is true for Balanced.
- Review `LivingRoomGraphicsEnhancer` duplicate apply calls and repeated scene discovery before optimizing smaller scripts.

### IntroPetSelection

- Lazy spawn pet previews instead of spawning the entire selected test roster.
- Use pooled preview instances for breed/fur cycling.
- Ensure selector props/trees/fences have mobile LODs and mobile texture settings.
- Keep post-processing off here unless it is required; the scene camera currently has post-processing off, which is good.

### Walking

- Build a mobile walking scene variant:
  - baked spline meshes
  - no SplineMesh runtime components
  - simplified road colliders or no road colliders for route movement
  - serialized route graph and allowed roads
  - fewer asphalt decal prefabs or decals baked into road textures
- Cull repeated city detail. Top repeated prefab families include:
  - 66 `Floor_300x300`
  - 27 `Fence_A`
  - 25 `TrafficCone_A`
  - 25 `Lamp_A`
  - 16 `Window_J`
  - 15 `Bush_A`
  - multiple asphalt damage decal prefabs
- Use a single visual pass for distant city set dressing; merge static props by material where SRP Batcher is not enough.

## Suggested Implementation Order

1. Add profiler markers and build a mobile profiling checklist for the three scenes.
2. Create a baked `Walking_Mobile` scene or build-time bake process for spline meshes and route colliders.
3. Split mobile URP renderer assets and disable decals/soft shadows in Battery and Balanced.
4. Implement lazy/pool-based Pet Selector preview spawning.
5. Extend mobile texture importer to 3D world asset folders.
6. Remove redundant scene scans and throttle Walking progress persistence.

## Profiling Checklist

Measure on target Android/iOS hardware, not just Editor:

- Cold scene load time for `David_Test`, `IntroPetSelection`, and `Walking`.
- Peak memory after each scene reaches interactive state.
- Main thread time, render thread time, GPU frame time.
- Batches, SetPass calls, triangles, vertices.
- Number of active MonoBehaviour `Update`/`LateUpdate` callbacks.
- Texture memory by asset family.
- Physics cost in Walking before and after mesh collider simplification.
- Shader variant warmup/stutter when pets and city props first appear.

## Quick Wins

- Disable Decal Renderer Feature in mobile Battery/Balanced unless Walking decals are essential.
- Set Balanced soft shadows off for test builds and compare visual delta.
- Serialize Walking allowed road colliders or route graph so `AutoAssignAllowedRoadsFromScene()` can be editor-only.
- Throttle `PushProgressToRuntime()` to a timer.
- Lazy spawn only current/adjacent pets in Pet Selector.
- Extend texture import caps to Japanese City Megapack and Dogs/Red Deer mobile textures.
